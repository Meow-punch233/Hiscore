## 浏览器反馈后的修复：异步删除与初中文案

### 已独立复现的根因
不是考试数量、`ui.examIdx` 或 IndexedDB 写盘失败导致本次已报告问题。
原删除处理器先 `await myConfirm(...)`，随后才读取 `ev.currentTarget`。
标准 DOM 在事件派发结束后会将 `event.currentTarget` 重置为 null；确认弹窗关闭后，
`btn.disabled = true` 因此抛出 `TypeError: Cannot set properties of null (setting 'disabled')`，
实际尚未执行 clone、splice、commitData，更没有打开快照数据库。

`implementation/reproduce-delete-before.cjs` 将保留的原处理器回灌到当前HTML，使用jsdom标准事件派发与真实异步确认框可重复复现。
证据见 `implementation/delete-root-cause-evidence.txt`：弹窗关闭、localStorage原文不变、Promise拒绝、SNAP.DB仍为null。
上一轮LinkeDOM测试未覆盖标准DOM对currentTarget的复位语义，确实漏掉了此问题。

### 修复
- 在首次await之前捕获按钮、目标考试引用、目标索引、当前页面和考试内容；全流程try/finally回收禁用状态。
- 同一删除流程加pending锁，防止确认期间重复触发；不改变「两次主动点击新建，应创建两场考试」的正常语义。
- 确认返回、快照事务提交后均校验目标未变，避免页面或选择变化时误删其他场次。
- 继续走原commitData及快照链路，不跳过IndexedDB、不关闭快照、不模拟成功。
- 删除失败可见反馈；写盘回滚未确认与提交后仅界面渲染失败分别说明，不伪称成功或无损。
- 成功后更新选择、重绘并提示已删除；持久化后刷新不会复活该记录。
- 同组件「清空示例，开始录入」存在相同的await后读取currentTarget问题，也已修复；同时保持初中默认规则与参考线隔离。
